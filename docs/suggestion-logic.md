# 次のコード候補の導出ロジック

このドキュメントでは、画面の「次の候補」に並ぶコードを決める処理の流れと、それを担うクラス・関数を説明します。

## 担当クラス

ロジックの本体は`chording::HarmonyAdvisor`（`Source/HarmonyAdvisor.cpp`）です。状態を持たないstatic関数2つで構成されています。

| 関数 | 役割 |
|---|---|
| `HarmonyAdvisor::estimateKey(history)` | 進行履歴からキーを推定する |
| `HarmonyAdvisor::suggest(current, key, style, mood, includeBorrowed, history)` | 候補を最大6件、スコアの高い順に返す |

呼び出し元は`ChordingAudioProcessorEditor::refreshModel()`（`Source/PluginEditor.cpp`）です。エディタのタイマー（20Hz）ごとに毎回計算し直すため、設定を変えるとすぐに順位に反映されます。

## 全体の流れ

1. キーを決める（`estimateKey`、またはユーザーが固定したキー）
2. 候補の元にするコードを決める
3. ダイアトニックコード7種と借用和音にスコアを付ける（`suggest`）
4. 上位6件を残す（`insertSuggestion`）

## 1. キーの推定

キー自動の場合は、進行履歴に「今押さえているコード」を足したものを入力にします。キー固定の場合は、設定したキーを確信度1.0でそのまま使います。

自動の場合は、24キー（12音×メジャー／マイナー）すべてに点数を付け、最も高いキーを採用します。点数は、履歴の各コードについて次の値を足し合わせたものです。

| 条件 | 点数 |
|---|---|
| ルートがそのキーのダイアトニック上にない | −2 |
| ルートがそのキーのダイアトニック上にある | +2 |
| その度数の性質と合う（メジャー系／マイナー系／Vの7th系／完全一致） | +2.5 |
| 主和音（I）である | +1 |

各点数には新しさの重み`1 + index / 履歴数`を掛けます。重みは最も古いコードで1.0になり、新しいコードほど2.0に近づきます。

確信度は`(1位の点数 − 2位の点数 + 1) / 6`を0〜1に収めた値です。履歴が空の場合はCメジャー、確信度0になります。

## 2. 元にするコード

元にするコードは「今押さえているコード」です。何も押さえていない場合は「履歴の最後のコード」を使い、履歴も空の場合は元のコードなしとして計算します。

## 3. スコアの付け方

### ダイアトニックコード

キーのI〜VIIの7種が候補になります。各候補のコードの性質は次のとおりです。

- ジャズ以外: 各度数のトライアド。ただしVは常にドミナント7th
- ジャズ: Vはドミナント7th、メジャー系はmaj7、マイナー系はm7、ディミニッシュはm7(b5)
- マイナーキーのVもドミナント7thになる（和声的短音階のV7）

元のコードとルート・性質が同じ候補は除外します。

各候補のスコアは次の合計です。

| 要素 | 点数 |
|---|---|
| 基本点 | +8 |
| 機能の流れ（`transitionScore`） | 下の表を参照 |
| スタイル: ポップ | I・V・vi・IV・ii・iii・viiの順に、+2.45から0.35刻みで+0.35まで |
| スタイル: ロック | I・IV・Vに+2 |
| スタイル: ジャズ | ii・Vに+3 |
| 印象: 明るい | メジャー・maj7の候補に+2.5（ドミナント7thは対象外） |
| 印象: 切ない | マイナー・m7・m7(b5)の候補に+2.5 |
| 印象: 緊張 | V・viiに+3 |
| 印象: 意外性 | viに+2 |
| viiのペナルティ | −2.5 |
| 共通音 | 元のコードと共通する音1つにつき+0.35 |
| 直前と同じルート | 履歴の最後のコードとルートが同じなら−3 |

履歴には140ms安定したコードが記録されます。そのため「直前と同じルート」の減点は、多くの場合、今押さえているコードと同じルートの候補に掛かります。

機能の流れの点数は、元のコードの度数から候補の度数への移動で決まります。元のコードの度数はルートだけで判定します。度数ごとの機能の分類は次のとおりです。

| 機能 | 度数 |
|---|---|
| トニック（T） | I |
| サブドミナント（SD） | ii・IV |
| ドミナント（D） | V・vii |
| 代理（relative） | iii・vi |

| 移動 | 点数 |
|---|---|
| D → T | +6 |
| SD → D | +5 |
| T → SD | +4 |
| V → vi（偽終止） | +4 |
| T → D | +3.5 |
| その他 | +1 |
| 元のコードのルートがキー外、または元のコードなし | 0 |

### 借用和音

借用和音の設定がONのときだけ、3つのメジャートライアドを候補に加えます。メジャーキーでは♭III・♭VI・♭VII、マイナーキーでは♭II・IV・I（ピカルディの3度）です。

スコアは基本点6に、ロック+4、ポップ+1.5、意外性+4、明るい−1を加えたものです。機能の流れと共通音の加点はありません。ダイアトニックコードと違い、元のコードと同じでも除外しません。

## 4. 上位6件の選び方

`insertSuggestion`が、ルートと性質が同じ候補の重複を除いたうえで、スコアの高い順に6件を保持します。同点の場合は先に評価した候補が上になります。評価する順番は、ダイアトニックのIからVII、続いて借用和音です。ダイアトニックの候補は除外があっても6件残るため、6件の枠は常に埋まります。

画面の役割ラベル（トニック／サブドミナント／ドミナント／代理／借用）は度数から決まります。説明文（「解決へ向かう緊張感」など）は、役割ごとの固定文言です。

## スコアの範囲

スコアはおおよそ3〜22の範囲に収まります。スタイルや印象の設定で全体が上下するため、設定の異なるスコアの絶対値どうしを比べても意味がありません。画面で順位や色分けに使う場合は、1位との差や順位などの相対値を使ってください。
